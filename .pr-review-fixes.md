## Finding 1 (Qodo, rule violation) — README not updated
Updated the "Plan validation" section in README.md (~line 274) to document: the
plan-artifacts fetch (`GET /api/sessions/{id}/plan-artifacts?chain=true`) paired with the
retained recap call for work rows / what's-done, automatic fallback to recap-only behavior
on older servers (404), and that degraded/truncated/unavailable plan states render explicit
marker lines (including the exit-code-2 behavior from finding 3).

## Finding 2 (Qodo, informational) — malformed truncated marker
Fixed `RenderPlanArtifacts` in `src/Capacitor.Cli/Commands/ValidatePlanCommand.cs`:
- `OriginalBytes` is nullable — a null value now renders `[plan truncated: first {n} of ? bytes]`
  instead of the malformed `of  bytes`.
- `content_state == "truncated"` with `Content == null` is now treated like `"unavailable"`
  (placeholder + "Validation is not possible" for the primary) instead of computing a
  nonsensical `first 0` byte count.
Added two new tests in `test/Capacitor.Cli.Tests.Unit/ValidatePlanCommandTests.cs`:
`Truncated_primary_with_null_original_bytes_falls_back_to_unknown_total_marker` and
`Truncated_primary_with_null_content_renders_like_unavailable`.

## Finding 3 (Qodo, review-recommended) — unavailable primary exits success
`HandleCore` now returns exit code 2 when the PRIMARY artifact's `content_state == "unavailable"`
(validation genuinely isn't possible) — distinct from 0 (normal render, or "no plan found": absence
is a valid answer) and 1 (transport/HTTP errors). `RenderPlanArtifacts` now returns a bool signaling
primary-unavailable, threaded through to the exit code. Updated/added test assertions for all three
exit-code cases (0 normal render, 0 no-plan, 2 unavailable primary) in `ValidatePlanCommandTests.cs`.

## Finding 4 (Codex, P2) — routed imports skip workspace_root
Only the file-based chain path (`ImportChainsAsync`) derived `workspace_root` via
`GitRepository.FindRoot`. Threaded the same fail-open derivation into the routed-import
session-start payload builders for OpenCode, Pi, Copilot, Kiro, and Antigravity
(`BuildSessionStartPayload` in each of their `*ImportSource.cs` files) — added
`if (cwd is not null && GitRepository.FindRoot(cwd) is { } workspaceRoot) ...["workspace_root"] = workspaceRoot;`
right after the existing `cwd` assignment in each. Cursor is intentionally untouched (its
`workspace_roots` is a separate pre-existing concept). Added two new tests in
`test/Capacitor.Cli.Tests.Unit/OpenCodeImportSourceTests.cs` mirroring
`ImportChainsTests.ImportChainsAsync_derives_workspace_root_from_the_remapped_cwd_not_the_raw_meta_cwd`:
`import_session_derives_workspace_root_from_cwd_when_a_git_repo_is_present` and
`import_session_omits_workspace_root_when_cwd_has_no_git_repo`.
